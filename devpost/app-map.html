What the app is

HowSure is a food log where every number says how much to trust it. It has three main pieces:

  • The maths core (src/kernel/): pure functions that turn meals into a total, an estimate score and two ranges, and sleep times into waking days. There's no screen code here, so every rule is tested on its own.
  • The screens (src/ui/): React components that draw the dashboard and the sheets, with all wording kept in src/ui/copy.ts.
  • The store (src/store/): reads and writes the log in the browser's localStorage, with the demo and your own log kept separate. Nothing leaves the device.

One action, end to end: "Improve that entry"

Reference route reference route; not a completed tour

  1. The button. src/ui/Dashboard.tsx, search for data-testid="improve-entry". It calls onImprove(biggest.id) for the meal the maths says adds the most uncertainty. The button is hidden when improve() returns null, meaning the meal already uses the most reliable source.
  2. The preview. src/ui/editMeal.ts, previewEdit(). It runs buildDayView(), the dashboard's own function, on a copy of the log with the edited meal, so the before/after preview and the dashboard after Save always match. The sheet itself is src/ui/LogMealSheet.tsx (search edit-preview).
  3. The maths. src/kernel/estimate.ts: combineDay() groups meals by source, adds each group's spread, combines the groups by the root of the sum of squares, and turns that into the score (scoreFromE()) and the ranges (rangeFromE()). improve() picks the better source to suggest. Saving goes through saveLog() in src/store/storage.ts.

A practice to reuse

Illustrations are not acceptance targets; compute expected results independently. During the PRD review, an example ("one 1,000 kcal meal at score 70 plus three 100 kcal meals at score 95 gives about 77") was kept as an illustration only. Instead, the spec required "independently calculated expected results" for the tests.

The build followed that: scripts/golden.py (Python, standard library only, never imported by the app) recomputes every case, and src/kernel/__tests__/golden.test.ts asserts the same numbers against the TypeScript code. The demo's headline moment, 2,280 → 2,380 kcal and score 83 → 92 (cases G11 and G11b), is checked both ways.

On another project: whenever an agent writes both the code and its tests, have the expected values come from a second, independent calculation (a script, a spreadsheet or a hand calculation), so the tests can't just echo the code's own mistakes.

How to run it again
  1. npm install
  2. npm run dev:app
  3. Open http://127.0.0.1:5273 and choose Try the fictional demo.
  4. Checks: npx vitest run, npx tsc --noEmit, npx playwright test.
